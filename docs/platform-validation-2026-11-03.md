# fnOS 平台验证与阻塞记录（P0）

- 记录日期：2026-11-03；文档状态复核：当前工作树静态源码核对。
- 结论：执行环境不是已验证的 fnOS 真机。本机识别结果为 Debian GNU/Linux 12、Linux x86_64（`uname -a`：`Linux nas 6.18.18.c1186-trim #1186 SMP PREEMPT_DYNAMIC Fri Oct 30 08:53:15 UTC 2026 x86_64 GNU/Linux`）。主机名/内核字符串不能证明运行的是 fnOS，也不能替代真实应用中心生命周期测试。
- 本地管理实现已增加私有 `supervisor-control.sock`，原生 Rust API CGI 兼容处理与静态 index CGI 也已存在；这些本地实现不等同于 fnOS 统一网关接入。本文没有新连网关或 UDS、发起真实鉴权请求、执行平台安装/升级/卸载回调，也没有使用真实用户数据。下表平台验收项仍阻塞。

## 平台门禁与需要的证据

| 阻塞项 | 当前已知/未证实 | 解除阻塞所需证据（仅在可丢弃的 fnOS 测试实例和隔离数据上取得） |
|---|---|---|
| 统一网关、路径前缀 | 目标仍是经 fnOS 统一网关发布；当前桌面配置仍指向 CGI，管理 HTTP 只监听回环 TCP。私有控制 UDS 仅供平台控制，不提供浏览器网关路由。未证明 manifest 所声明最低 fnOS 1.0.0 支持目标网关能力。 | 在最低声明版本和明确的当前目标版本上，从实际应用中心安装候选包；记录网关注册配置、请求与响应，验证前缀是否保留/剥离、静态页/API 路径、尾斜线、GET/POST/HEAD/404/405，以及桌面入口、浏览器与手机 App 均走同一路径。文档或模拟反代不算真机证据。 |
| 网关 UDS / Socket 生命周期 | 本地已实现 `${var_dir}/supervisor-control.sock` 私有控制 UDS，权限 0600 并用 `SO_PEERCRED` 核验 peer UID；它不是 fnOS `gatewaySocket`。本环境没有经确认的 fnOS gatewaySocket 运行时或平台身份，网关 Socket 路由、属主、权限、重启和清理语义均未验证。 | 从目标 fnOS 实例取得官方接口配置与真实网关 Socket 路径；记录 `stat`/属主/权限、网关与应用进程身份、连接成功请求、服务/系统重启后的 Socket 生命周期、断连和陈旧 Socket 场景。验证未知属主/普通文件占位不会被应用删除；保存可复核的配置、命令输出和日志。 |
| 网关鉴权、管理员授权与 CSRF | manifest 静态声明 `disable_authorization_path=false`；这不是实测的用户/角色授权结论。`api.cgi` 是 Rust 原生处理的迁移期兼容桥，现有 token/CSRF 处理不构成 fnOS 网关登录或管理员授权证据；尚无真实网关 Header 覆盖、Cookie 或非管理员拒绝证据。 | 用真实登录态分别测试未登录、普通用户、管理员、过期会话；对比合法/缺失/伪造 `X-Trim-*`、客户端同名 Header 覆盖、CSRF 缺失/错误、跨站 Origin、GET/HEAD 与变更方法；同时覆盖 HTTPS 反代、手机 App 和 SSE。保存脱敏后的请求/状态码/响应头与网关日志，不记录 token/cookie。 |
| `install_init` 与安装阶段执行窗口 | 当前 `cmd/install_init` 仅 `exit 0`；尚未验证 fnOS 调用顺序、应用包是否已解包、原生程序在该阶段能否执行、工作目录/用户/环境变量/输出如何处理。 | 在空白可丢弃实例安装当前测试包，采集平台生命周期阶段顺序、每个回调的 cwd、运行用户、TRIM 环境、目标文件存在性与执行位、stdout/stderr、退出码及 `TRIM_TEMP_LOGFILE` 内容。证明目标原生文件在拟使用阶段可执行；用隔离路径确认失败会由应用中心报告而非假成功。 |
| 外壳 upgrade 回调窗口 | `cmd/upgrade_callback` 是转发 Rust `platform upgrade` 的薄入口；Rust 负责监督者停止/重启及需要时的精确环境修复。源码不能证明升级时新旧 target 的替换顺序、callback 所在位置或重试语义。 | 从已安装旧版升级可丢弃实例，逐阶段记录包解压/旧 target 替换/回调的先后、文件 hash/执行位、`TRIM_APPDEST` 与主进程状态；测试平台重试、回调失败与恢复后路径。证明 callback 所在窗口所需程序确实可执行且不会误操作共享数据。 |

| 真实应用授权与桌面注册 | `.url` 和 manifest 只给出静态声明；未证明动态更新 `noDisplay` 是否被平台采纳、是否需重新注册、iframe 与 URL 桌面项是否按预期打开。 | 在实际 fnOS 桌面检查新装、内核安装/卸载、端口修改后入口显示与点击行为；记录 `ui/config` 前后内容、应用中心/桌面缓存刷新步骤、授权设置和重启后状态。静态 JSON 变化不能当作 UI 实测。 |

## 解除平台阻塞的安全条件

1. 所有平台操作都在可丢弃的 fnOS 测试实例上进行，先做快照；数据使用专门构造的临时账户/夹具，不连接生产部署，不操作真实用户数据。
2. 证据需同时给出 fnOS 版本、FPK 版本和 SHA256、回调阶段与时间、执行用户、入口路径/权限、实际请求与状态码、关键日志及清理结果；敏感认证值必须脱敏。
3. 最低兼容版本无法取得、目标网关/UDS 不可用、鉴权边界不能验证、或 uninstall 时没有可证明的原生执行窗口，都保持阻塞。不能通过提高最低版本、开放公开端口、跳过鉴权测试或退回 Shell 删除逻辑来消除记录。
4. 上表各项均为“未实测/阻塞”，不是失败也不是通过；后续验证应按管理整改计划 P0/L6 的门禁继续记录，不把静态源码、CI、文档或历史 FPK 校验扩写成真机结果。
